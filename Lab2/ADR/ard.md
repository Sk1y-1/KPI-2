### ADR-1: Склад акторів для одиночної гри: Steam як зовнішня система замість Auth Provider

# Контекст
Домен: одиночна 2D survivors-like гра. Завдання вимагає щонайменше два типи акторів: людина та зовнішня система/сервіс.

# Проблема та альтернативи
Яку зовнішню систему обрати, якщо гра одиночна й окремих акторів-користувачів немає?

# Альтернатива 1: Auth Provider та абстрактний актор «Власник облікового запису»
Опис: зовнішній сервіс автентифікації, вхід у систему як окремий UC.
Плюси: класичний приклад зовнішньої системи.
Мінуси: для одиночної гри автентифікація не потрібна, Player лише локальний профіль. Довелося б вигадувати додаткові поля та UC без реальної потреби гравця.

# Альтернатива 2: Steam (Steam Cloud)
Опис: зовнішня система, яка зберігає прогрес гравця в хмарі.
Плюси: реальна потреба актора (продовжити гру на іншому пристрої); природний зв'язок extend для UC-3.
Мінуси: прив'язка до платформи; у моделі даних немає полів для розв'язання конфліктів синхронізації.

# Альтернатива 3: Без зовнішньої системи
Опис: гра повністю офлайн.
Плюси: найпростіша специфікація.
Мінуси: не виконує вимогу «людина + зовнішня система» (та також можливо в майбутньому буде coop)

# Рішення
Обрано Альтернативу 2. Актори: Гравець, Гейм-дизайнер (спеціалізація Гравця, бо теж запускає забіги для перевірки балансу) і Steam.

### ADR 2: 2: Поведінка при старті нового забігу за наявності незавершеного: попередження замість блокування.

Контекст

Початкова версія вимоги вимагала відхиляти запит на старт нового забігу, поки в гравця є незавершений.

Проблема та альтернативи

Що має відбуватися, коли гравець запускає новий забіг, маючи незавершений?

 # Альтернатива 1: блокувати старт
Опис: WHILE є незавершений забіг, система відхиляє запит.
Плюси: простота; випадкова втрата даних неможлива.
Мінуси: при збої гри поле end лишається порожнім, і гравця заблоковано без виходу.

# Альтернатива 2: попередження з підтвердженням
Опис: система попереджає про втрату незавершеного забігу; після підтвердження він стає «покинутим», після скасування лишається без змін.
Плюси: немає глухого кута; рішення за гравцем.
Мінуси: потрібне поле статусу забігу; більше вимог.

# Альтернатива 3: автоматичне завершення без запиту
Опис: незавершений забіг мовчки закривається при старті нового.
Плюси: найпростіша поведінка.
Мінуси: гравець може випадково втратити прогрес.
Рішення

Обрано Альтернативу 2: попередження та підтвердження.
